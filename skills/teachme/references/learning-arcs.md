# Learning Arcs

Use this reference only when the learner's goal spans multiple dependent skills, sessions, or consequential mastery claims. Skip formal arc machinery for a small lesson.

## Two levels

```text
LEARNING ARC
  goal → capability map → current phase → trajectory checks → final proof
                              │
                              ▼
                         CURRENT SKILL
                              │
                              ▼
                          RUNG LOOP
```

The Rung loop teaches the current skill. The learning arc decides whether that skill is still the right next work given the larger goal.

## Bootstrap

Use:

```text
inspect actual performance
→ define observable independent DONE
→ map required capabilities backward
→ challenge the weakest roadmap assumption once
→ choose the first meaningful bottleneck
→ execute forward with the Rung loop
→ adapt from evidence
```

Rules:

- Build the roadmap from demonstrated reality, not learner self-rating alone.
- Make the final proof resemble real future use.
- Keep distant phases broad; detail the current phase and next skill.
- Order by dependencies and bottlenecks, not by textbook convention alone.
- Treat the capability map as provisional.

## Canonical arc state

Keep one current view, not a new progress summary every session:

```text
ARC GOAL:
FINAL INDEPENDENT PROOF:
CURRENT PHASE:
CURRENT SKILL:
CURRENT STATUS:
CAPABILITY MAP / ROADMAP:
VERIFIED STRENGTHS:
ACTIVE WEAKNESSES:
PREREQUISITE BLOCKERS:
MASTERY EVIDENCE:
ACTIVE REGRESSION CASES:
NEXT EXERCISE:
USEFUL BUT LATER:
```

Old sessions are evidence/history, not competing current truth.

## Trajectory check

Run at natural boundaries, for example after a phase, when repeated prerequisite gaps change the plan, when a supposed weakness proves strong, when progress plateaus, or when remaining roadmap items stop matching the final proof.

Use:

```text
re-check evidence
→ name what changed
→ compare roadmap with final proof
→ choose action
→ update canonical state
→ continue
```

Actions:

- `CONTINUE`
- `REPRIORITIZE`
- `INSERT PREREQUISITE`
- `CUT`
- `RESEARCH`
- `REDESIGN PRACTICE`
- `TEST MASTERY`
- `STOP`

If the learner changes the objective itself, re-orient and redefine the final proof.

## Anti-ceremony

- Do not formalize one-off lessons.
- Do not require fields that change no teaching decision.
- Do not preserve every mistake.
- Do not create parallel status trackers.
- Do not let a written roadmap outrank new learner evidence.
- Stop when the agreed final proof passes.

This is a Rung design adaptation from MAPS_Lean project bootstrap and roadmap trajectory control, not a validated educational protocol.
